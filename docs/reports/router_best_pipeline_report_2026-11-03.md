# best-v1: ゼロショット ruri 固定の end-to-end 最良パイプライン（2026-11-03）

**状況**: 完了。test は一回のみ評価した。

## 構成（ruri はゼロショット固定、FT モデルは使わない）
1. 候補: sr top-8 に kNN 補完を足す。kNN は e5-small で dev をメモリにし、M=10 近傍の gold 投票から sr に無いツールを最大 3 件加える（候補にはテーブルのヒットも含む）。
2. fusion: ロジスティック回帰。特徴は sr p / sr 順位 / sr 内か / ruri / 既存 fusion 確率 / conv / kNN 投票 / kNN 1位か / テーブルスコア / テーブルヒット。C は dev の 5-fold（グループ）CV の対数尤度で選ぶ。
3. 補正テーブル: NFKC・カナ→ひらがな・エイリアス・語尾除去・pykakasi 読みの Dice で照合する。τ は dev で調整し（異ゴールド誤一致 ≤2%）、**pin はせず**特徴量（ソフトブースト）としてだけ使う。
4. デファーゲート: LightGBM（4 leaves、λ=10、3 seed）と LR+標準化の 2 種。特徴は 15 個で、kNN 一致とテーブルヒットを含む。動作点は dev CV 上で「最大 cascade Top-1 から 1pt 以内に収まる最小デファー」として選ぶ（test は見ない）。
5. LLM: 既定は記録済みの全リスト LLM 選択（past）。比較用に **SIMULATED** の逐次 yes/no（top-3、false-yes 0/10/20/30%、20 MC）も評価する。

グループ CV の単位: 会話。ただし "main" 会話が 288/394 件を占めるので、main は seq 20 ターンごとのブロックに分けた。

## CLI
```
bun run router correct --db data/bench-r2.db --variants … --controls … --rerank ruri --table 1 --python PY --out DIR   # 前処理（sr/past/ruri/読み/e5）
bun run best-v1 -- --corr DIR --out OUT --python PY                                                                         # 本体
```

## 結論（先に）
- **最も効いた組み合わせは「sr∪kNN 候補 + LR fusion（kNN 特徴あり）+ margin ゲート」（= +lr(knn)）でした。** test 217 で Top-1 **89.4** / デファー **26.7%**。baseline 比 **+7.8 [2.3, 13.4]**、本 run の E2 比 +0.9 [−0.9, 2.8]（有意差なし）。Top-1 90 に届くデファーは **23.0%** で、そこに届いたのはこの構成だけでした。
- **学習ゲート（GBM/LR）は逆効果でした。** best-v1（全部入り、GBM）は 88.9 / デファー **52.1%**。dev CV の「最良から 1pt 以内」ルールが保守側に倒れ、デファーが倍近くになりました。LR ゲートでも 86.6 / 34.6%。margin ゲートに戻すと 88.5 / 29.5%。
- **補正テーブル（pin なし、特徴量のみ）は、静的な test では ±0〜−0.9 でしたが、補正後の variant 修正では効きました。** variants fix は **27.1%**（テーブル無しでは 4.9%）で、misfire は 1.0%。
- 頑健性（全データでの blocked 5-fold×3 seed）: best-v1 は **87.7±3.9**、E2 は 86.1±5.6、baseline は 80.4±5.9。時系列分割（main 会話）の 3 点すべてで best-v1 > E2 > baseline でした。
- LLM 逐次 yes/no の SIMULATED（best-v1 のデファー集合）: false-yes 0/10/20/30% でそれぞれ 97.2 / 95.6 / 93.8 / 92.2。**楽観的な上限です**（top-3 に gold があれば yes と答える仮定）。実 LLM では未測定。
- 注意: baseline は 70.0 / 81.6 / 29.5 と完全に再現しました。一方 **E2 は 88.5 で、round 4 の 91.7 は再現しませんでした**（ゲートや特徴の実装差と思われますが、原因は未特定）。

## 6. 推奨と次の一手
1. 本番候補は **+lr(knn) + テーブル特徴 + margin ゲート**。静的な精度は 88.5〜89.4 で、補正後の variant 修正も効きます。GBM ゲートは不採用。
2. E2 91.7 が再現しない理由を、round 4 の algo4.py との差分（ゲートの閾値の決め方）で特定する。
3. 逐次 yes/no を実 LLM で測る（未測定）。
4. FT ruri（後回し分）は、この fusion の rr 特徴を差し替えるだけで評価できます。

再実行: `bun run best-v1 /tmp/corr/e4 OUT /tmp/cvenv/bin/python`（HF_HUB_OFFLINE=1、モデルはキャッシュ済みが前提）。
