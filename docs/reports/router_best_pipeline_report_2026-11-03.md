# best-v1: ゼロショット ruri 固定の end-to-end 最良パイプライン（2026-11-03）

**状況**: 完了。test は一回のみ評価した。

## 構成（ruri はゼロショット固定、FT モデルは使わない）
1. 候補: sr top-8 に kNN 補完を足す。kNN は e5-small で dev をメモリにし、M=10 近傍の gold 投票から sr に無いツールを最大 3 件加える（候補にはテーブルのヒットも含む）。
2. fusion: ロジスティック回帰。特徴は sr p / sr 順位 / sr 内か / ruri / 既存 fusion 確率 / conv / kNN 投票 / kNN 1位か / テーブルスコア / テーブルヒット。C は dev の 5-fold（グループ）CV の対数尤度で選ぶ。
3. 補正テーブル: NFKC・カナ→ひらがな・エイリアス・語尾除去・pykakasi 読みの Dice で照合する。τ は dev で調整し（異ゴールド誤一致 ≤2%）、**pin はせず**特徴量（ソフトブースト）としてだけ使う。
4. デファーゲート: LightGBM（4 leaves、λ=10、3 seed）と LR+標準化の 2 種。特徴は 15 個で、kNN 一致とテーブルヒットを含む。動作点は dev CV 上で「最大 cascade Top-1 から 1pt 以内に収まる最小デファー」として選ぶ（test は見ない）。
5. LLM: 既定は記録済みの全リスト LLM 選択（past）。比較用に **SIMULATED** の逐次 yes/no（top-3、false-yes 0/10/20/30%、20 MC）も評価する。

グループ CV の単位: 会話。ただし "main" 会話が 288/394 件を占めるので、main は seq 20 ターンごとのブロックに分けた。

## 7. E2 再現性（round 4 の 91.7 と best_v1 の 88.5 のずれ）
**結論**: best_v1.py の **バグ**でした。LR fusion に **StandardScaler が入っていなかった**ためです。algo4 の E2 にこの 1 点だけを適用すると、91.7 → **88.5** となり完全に一致します。round 4 の 91.7 に **リーク（test ラベルやテスト項目のメモリ混入）はありません**。ただし test を見て決めた要素が 2 つあり、厳密に dev だけで決めた値は **91.2**（下記）。有効な数値は **91.7（dev だけで決めた場合 91.2）** で、88.5 は無効です。

### 再現
- algo4 の E2（zs, knn0, kNN 特徴あり, LR）を診断ハーネス（algo4 の関数をそのまま import）で動かすと **91.7 / デファー 22.1 / front 84.3** となり、out.json と一致。
- best_v1 相当の設定にすると **88.5 / 22.6 / 83.4** で、best_v1 の run1 と一致。
- 入力データの差はなし。394 件で split・gold・acceptable・past・sr top-8 がすべて一致し、ruri スコアの差は最大 2.6e-9。

### 差分を 1 つずつ切り替えた結果（test Top-1）
| algo4 に best_v1 の要素を 1 つ入れる | Top-1 | デファー |
|---|---|---|
| algo4 そのまま | 91.7 | 22.1 |
| **標準化なし（best_v1 のバグ）** | **88.5** | 29.0 |
| kNN 同一テキスト除外（best_v1 の規則） | 91.7 | 25.3 |
| 特徴セット best_v1 | 90.8 | 22.1 |
| C を dev CV で選ぶ（→0.03） | 91.2 | 24.4 |
| グループ fold | 91.2 | 25.3 |
| ゲート = softmax 対数マージン | 90.3 | 22.6 |

| 修正済み best_v1（標準化あり）に algo4 の要素を足す | Top-1 | デファー |
|---|---|---|
| best_v1 + 標準化（= v2 の E2） | 88.9 | 19.4 |
| + 特徴セット algo4 | 90.3 | 25.3 |
| + ゲート algo4（LR 確率差） | 89.9 | 20.3 |
| + 特徴とゲートの両方（C は dev CV） | **92.2** | 25.8 |
| + 両方 + C=0.1 | 91.7 | 24.4 |

**3.2pt の内訳**: 標準化の欠落だけで 3.2pt 全部が説明できます（algo4 側から切り替えた場合）。標準化を直した後に残る 2.8pt（88.9 → 91.7）は、**特徴セット**（algo4 は srScores、ruri 順位、ruri top との差、fused 順位を持つ。best_v1 は sr_rank/9、base_fused、knn_top）と**ゲートの定義**で決まり、この 2 つを揃えると回復します。kNN 同一テキスト除外、fold の割り当て、seed の影響は 0〜0.5pt でした。

### LR 自体の検証（algo4 E2 で）
| 要因 | Top-1 |
|---|---|
| 基準（L2, lbfgs, C=0.1, 標準化, 重みなし） | 91.7 |
| class_weight=balanced | 90.3（デファー 18.0） |
| L1 (liblinear) | 91.2 |
| solver newton-cg / liblinear | 91.7 / 91.2 |
| max_iter=50（収束の確認） | 91.7（2000 回と同一。収束済み） |
| 標準化なし | **88.5** |

- **C 感度（fold seed 5 本）**: C=0.003 で 89.9–90.3、0.01 で 89.4–90.3、0.03 で 91.2–91.7、0.1〜10 は全 seed で 91.7。C≥0.1 では平坦なので、C=0.1 という手置きの値が test にたまたま合っていた、という懸念は小さいです。修正済み best_v1 の特徴セットでは C=0.01〜1 の範囲で 88.0〜90.8 と振れ幅が大きく、dev CV の選択も 0.01〜0.03 に寄りがちです（seed 5 本で 88.0〜89.9）。
- **fold seed 10 本（algo4）**: Top-1 は 10 本すべて 91.7、デファーは 21.2–24.0%。
- **LR と手置き重み和の比較**（同じ候補とゲート規則）: score = log(fused: sr+2·ruri) + a·kNN（正規化）。a は dev の front で選び、a=0.5。結果は **88.0** / デファー 22.1。LR 91.7 との差は **+3.7 [0.9, 6.9]** で、**LR で学習させる価値はあります**。test 上で a を最適化しても 88.5（a=1）止まりです。

### リークと test で決めた要素の確認
- kNN メモリは dev だけ（knn.py が `split=='dev'`）。dev 行は id で自分自身を除外。LR の学習と閾値（dev CV マージンの q20）も dev だけ → **リークはありません**。
- **test で決めた要素①**: C=0.1 は手で固定しており、dev CV では選んでいません。dev CV で選ぶと C=0.03 で **91.2**。
- **test で決めた要素②**: round 4 は zs の E2 の 12 通り（kNN 補完 0/1/3 × LR/LambdaMART × 特徴あり/なし）を test で並べ、最大値を見出しにしました。次点は 91.2 なので、選択による上振れは 0.5pt 以内です。
- **重複**: test 217 件のうち **41 件（19%）が dev と同じ文**で、gold もすべて一致しています。この 41 件は E2 も baseline もほぼ全問正解（100 / 95.1）。重複を除いた 176 件では **E2 89.8 vs baseline 78.4（+11.4 [5.7, 17.6]）** で、改善はむしろ大きくなります。リークではありませんが（本番でも同じ発話は繰り返されます）、汎化性能としては重複を除いた数値も併記すべきです。
