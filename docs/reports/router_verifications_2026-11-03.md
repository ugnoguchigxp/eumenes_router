## 5. 訂正の記憶（すぐ効く訂正）

本番の関数（`nearFeedback` → `correctProbabilities`）で測った。θ は dev で決めた: 意図の違う dev の組 13,632組の 1% 以下しか超えない値 = **0.9177**。

best-v2 につなぐだけでは効きが弱い（LARM 版、β 2: 訂正した発話 34.5%、言い換え 20.0→45.7%）。外れた test の約半分（34件中15件／29件中15件）は正解が best-v2 の候補にない。補正は候補の中でしか効かないので、`route()` が近い訂正の正解を `include` で候補に足すようにした。

β は dev で決めた（LARM の点数を検索と融合した Router に、正解を候補に足す。dev で訂正を入れ、関係ない dev 発話の崩れを1位で見る）:

| β | dev の訂正した発話 | 関係ない dev 発話の崩れ（141件） |
| --- | --- | --- |
| 1 | 72.2% | 0.0%（0〜0） |
| **1.5** | 72.2% | **0.0%（0〜0）** |
| 2 | 72.2% | 0.7%（0〜2.8） |
| 3 | 72.2% | 3.5%（0.7〜6.4） |
| 5 | 72.2% | 12.1%（7.1〜18.4） |

崩れの 95% 上限が 1% 以下の最大で β = 1.5（dev は LARM の学習に一部使われ崩れにくく出るので上限で決めた）。test で1回:

| 指標（test、LLM なし） | 候補に足さない | 候補に足す（決定） |
| --- | --- | --- |
| 訂正した発話をもう一度 | 47.6% | **85.7%** |
| その言い換え: 前 → 後（直った率） | 26.7 → 60.0%（45.5%） | **26.7 → 78.0%（70.9%）** |
| 関係ない発話の崩れ（166件） | 0% | **0%** |
| 訂正していない言い換えの崩れ / 対照 | 1.0% / 0 of 40 | 0.7% / 1 of 40 |

plan の基準（回復率 ≥ 90%、副作用 ≤ 1%）のうち回復率は未達。この値は e5 small の空間のもので、本番の埋め込み（LARM）では同じ手順で決め直す。test で見た感度（β 2 で関係ない発話の崩れ 4.8%）は選択に使っていない。

## 6. 残り

- best-v2 は bench の Python で、パッケージに入っていない。best-v2 に「候補に足す」をつなぐには、足した候補の採点し直しが要る。
- 正解付け（M1）、本番機の速度と会話 LLM への干渉、新しい担当の cold start、旧経路のトークンは未測定。
