# Router 第4ラウンド: ruri 以外のアルゴリズム検証（2026-11-03）

**結論（先に）**
- **E7 上限**: zs の誤り40件は retrieval 9 / rank・ゲート見逃し 15 / LLM 16 件。完全ゲートなら 93.1、完全 reranker＋完全ゲートなら 98.6。FT 後（cp）は retrieval miss が最大要因になる。
- 一番効いたのは **kNN（dev をメモリにした近傍投票）**。候補を補完すると R@10 は 93.1 → 98.2 に上がる。fusion の特徴量に入れると、zs ruri の Top-1 は 81.6 → **91.7**（+10.1 [5.1, 15.2]）になる。ただし FT ruri（cp）に足しても上積みはない。dev ラベルの知識を FT とは別経路で注入しているだけと解釈している。
- 学習したデファーゲート（E1）は zs で少し改善する（GBM なら Top-1 81.6 に必要なデファーが 30.0% → 25.4%、kNN 併用時）。cp1/cp2 では ±1 で効果なし。
- 候補数（E5）は sr の k=5 で頭打ち。LLM に渡す候補を top-n に絞ると、どの n でも全リスト時（81.6）を下回る。
- 手続き型 LLM（E6、**SIMULATED**）は (a) 逐次 yes/no が最良（fy=0 で 87.1、0.60 回/件）。ただし false-yes が 20% あると 82.3 まで落ちるので、yes-bias への感度が大きい。

## 条件
- データは dev 177 / test 217。チューニングは dev のみ（held-dev または dev 上の 5-fold CV）で行い、test は1回だけ評価した。
- ベースライン: sr + ruri → LLM、w=2、conv=0.18、閾値は held-dev マージンの20%分位。CI は test 上の paired bootstrap 95%。
- rerank 入力は zs（ゼロショット ruri）と cp0–2（FT k10 conv-positive、seed 0–2）。cp の held-dev は学習 id を除いた 72 件。
- **過学習リスク**: dev は n=177 しかない（cp は 72 件）。E1/E2 の LightGBM は強く正則化している（4 leaves、λ=10）が、差の CI は広い。
- LLM の判断は記録済みの past choice を使ったシミュレーション。外部 API は使っていない。

- cp0/cp1/cp2 では誤りが 32/27/24 件。retrieval miss が 13/10/10 件と最大要因になり、LLM 誤りは 7–8 件まで減る。FT 後に残る主なレバーは**候補補完（kNN）とゲート**。
- E1 の gap 閉鎖率（同一デファー、完全ゲート比）: zs GBM の at29.5 は (83.0−81.6)/(93.1−81.6) ≈ 12%。cp1/cp2 は ±1 で約 0%。
- E2 の gap 閉鎖率（完全 reranker の front 比）: zs は kNN 無しで約 0–12%（70.0 → 70.5–72.8 / 93.1）、kNN 特徴ありの LR で (84.3−70.0)/(93.1−70.0) ≈ 62%。cp0 は kNN 無しで (82.0−74.7)/(93.1−74.7) ≈ 40% だが、cascade Top-1 は ±2 にとどまる。

## E3 kNN 候補補完（e5-small、M=10、dev 行は leave-one-out）
- test で gold が sr top-8 に入っていないのは 15 件。補完で回収できたのは N=1 で 11 件、N=3 で 13 件、N=5 で 14 件（dev は全 N で 12/13 件）。
- R@10 は 93.1 → 98.2（zs、N=1）。ただし zs の front/cascade Top-1 は変わらない（追加候補が ruri で上位に来ない）。
- cascade Top-1 は cp0 で 85.3 → 86.2、cp1 で 87.6 → 88.5。

## E2 学習 fusion ランカー（sr top-k 上の LR / LambdaMART）
- kNN 特徴なし: zs は front 70.5–72.0 で改善なし。cp は front が +2〜+6 上がる（cp0 は 74.7 → 82.0）が、cascade Top-1 は ±2 にとどまる。
